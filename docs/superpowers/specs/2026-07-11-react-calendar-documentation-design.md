# React Calendar Documentation Design

**Date:** 2026-07-11
**Status:** Approved

## Goal

Make the npm page and introductory React documentation explain the real API in plain language, without undefined example components or invented data.

## npm README

The README starts with one short `useCreateCalendar` example that enables month, week, and day views. It uses a concrete `Event` type, real `Temporal.PlainDate` values, controller navigation, view switching, and the discriminated `activeView` returned by the shipped hook.

The example deliberately uses plain HTML instead of hiding behavior behind styled calendar components. It stays short enough to scan on npm and links directly to the complete runnable multi-view example on the website.

Suspense is presented as an optional composition pattern, not the default learning path. The README explains its purpose in two sentences and links to the complete website guide instead of showing an incomplete snippet.

## Website documentation

The React introduction repeats the same real mental model: one hook owns the date and active view, `activeView` contains the projected month/week/day data, and the consumer owns markup and styles.

The first-calendar page and its live basic-month preview teach the smallest month-only simple mode before pointing to the complete multi-view example. The Suspense, provider, and `useCalendarView` pages use locally complete examples: every component, query option, and returned field shown in a snippet is declared in that snippet or is a documented imported API.

Example pages use short descriptions that state what their live example demonstrates. Links from npm target the exact `/calendar/docs/examples/multi-view` and `/calendar/docs/data-and-suspense` routes generated by the site.

## Agent documentation

The documentation generator must treat `(react)` as a route group, not a public URL segment. Generated `llms.txt` links therefore use `/calendar/docs/...` for React pages and `/calendar/docs/core/...` for Core pages.

The generated Calendar skill uses the same real quick-start model as the npm README. It installs the React calendar package and the directly imported Temporal polyfill, uses shipped view properties, and links to the complete Suspense guide instead of making TanStack Query appear required.

## Truthfulness rules

- Every package import must exist in `packages/react/src/index.ts` or its re-exported core API.
- Every view property must exist in the shipped `MonthView`, `WeekView`, or `DayView` types.
- No introductory snippet may reference `ActiveView`, `CalendarContent`, `CalendarControls`, `CalendarSkeleton`, `MonthGrid`, `monthQuery`, or `eventsQuery` unless it defines that value locally.
- Example dates and events must be concrete Temporal values, not comments or pseudocode.
- Styled presentation components remain website-local and are never described as package exports.

## Verification

- Search introductory docs for known undefined placeholder identifiers.
- Type-check the React package and documentation website.
- Build the React package and documentation website.
- Regenerate `llms.txt` and the Calendar skill, then confirm they contain no `/docs/react/` URLs or required TanStack Query installation.
- Inspect the final diff for concise language and correct links.

## Non-goals

- Changing the React or core APIs.
- Adding a styled calendar component to the headless package.
- Teaching data fetching or Suspense on the npm page.
- Publishing or deploying the package or website.
